# Web Design Studio

Use for a website build or redesign in the user's chosen project. Inspect the existing app and its project instructions before editing. Preserve its framework and working behavior.

Read the locally available design skill first. Route to design-system for tokens, brand for voice, ui-styling for components, and ui-ux-pro-max for layout decisions when relevant. These skills already ship in DATA's core bundle. This pack is an original workflow, not a replacement for their scripts or reference files. If a named skill is missing, report it and use the existing project conventions; do not silently download a replacement.

Resolve the audience, primary action, essential sections and supplied assets from the task. Ask only for missing decisions that change the work. Offer one suitable starting direction:
- Editorial: warm neutral surfaces, strong type hierarchy, restrained color and generous reading space.
- Product: clear navigation, compact comparison sections and prominent action states.
- Portfolio: image-led project stories, visible credits and accessible media.

Implement the authorized local build with semantic controls, keyboard focus, responsive layouts, readable contrast and real loading, empty and error states where applicable. Use supplied images or licensed assets. Never invent testimonials, client logos or business claims.

Verify the main user flow and mobile layout with the project's available checks. Hand off the preview address, changed files and any limitations. Deployment, domain purchases and paid image or API calls remain separate actions requiring the user's applicable approval.

Example brief: "Redesign this local photography site for wedding inquiries. Keep the existing gallery and contact form. Use the editorial direction."

These instructions support the user's task. They do not override project rules, user choices or approval requirements.
