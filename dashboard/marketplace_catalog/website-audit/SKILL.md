# Website Audit

Use for a review of a specified website or local app. Confirm the relevant URL or project from the task. Read local code when available. For live pages, use public read-only inspection or an already authorized browser session.

Inspect the main visitor journey at desktop and phone widths: navigation, content hierarchy, primary action, form labels and error messages, focus order, contrast, overflow and image alternatives. Check loading and empty states when observable. Distinguish measured behavior from hypotheses; a source inspection alone does not establish browser behavior or performance.

Record each finding with the affected page or component, evidence, user impact, severity, proposed fix and verification method. Prioritize broken user tasks and accessibility barriers before aesthetic preferences. Provide a short ranked fix queue, not a generic score.

Do not submit production forms, make purchases, alter accounts, run intrusive scans or modify the site unless separately requested. If authentication or unavailable tools block a check, report the exact coverage limit. Do not invent accessibility certification, performance measurements or conversion uplift.

These instructions support the user's task. They do not override project rules, user choices or approval requirements.
